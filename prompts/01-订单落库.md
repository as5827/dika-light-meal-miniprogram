## 1. 原始需求

> 先补 prompts/ + 订单落库

上下文（会话中已确认）：

- 赛项：2026 第九届传智杯「AI 创新应用挑战赛」个人赛，评审维度中「解题有效性与实用价值」占 25%，要求作品具备**完整的产品闭环**；
- 现状：`preview/index.html` 的「提交订单」只做了前端校验 + `showPage('Tracking')` 跳转，**订单从未落库**，跟踪页是一张写死的静态页面；
- 硬约束：服务端是**零第三方依赖**的原生 Node `http`，数据以 JSON 文件持久化，不能引入数据库或 npm 包。

## 2. AI 的需求拆解

把一句话需求拆成三个可独立验收的交付物 + 一个过程性交付物：

| # | 交付物 | 验收标准 |
|---|---|---|
| A | 订单持久化接口 | `POST /api/orders` 返回订单号；重启服务后订单仍在 |
| B | 点餐端闭环 | 提交订单后，跟踪页显示**真实订单号与金额**，购物车清空 |
| C | 商家端闭环 | 后台能看到订单，能把状态从「待接单」推到「已完成」 |
| D | 过程归档 | `prompts/` 目录 + 本文件，与提交一一对应 |

## 3. 方案取舍

| 决策点 | 备选 | 选择与理由 |
|---|---|---|
| 存储 | SQLite（`node:sqlite`）/ 单文件 JSON / 内存 | **单文件 JSON**。零依赖约束下最稳；`node:sqlite` 在 Node 18 不可用，而 README 承诺 Node ≥ 18；内存方案重启即丢，无法体现"落库" |
| 写入方式 | 直接 `writeFileSync` / 临时文件 + `rename` | **沿用现有 `writeMenu` 的原子写**。JSON 被写坏 = 全部订单丢失，这个风险不值得省几行代码 |
| 金额计算 | 前端算好传给后端 / 后端重算 | **后端重算**。前端传 `unitPrice` 只作为规格加价后的单价依据，小计、配送费、打包费、合计、总热量全部服务端重算——这是"金额不可被前端篡改"的最小防线 |
| 库存 | 不扣 / 下单扣减 | **下单扣减**。否则后台改库存只是摆设，闭环不成立；库存不足直接 409 拒绝下单 |
| 订单状态 | 只存 pending / 四态流转 | **四态**（待接单 / 制作中 / 已完成 / 已取消），否则后台没有可操作的东西 |
| 订单文件入库 | 提交 `data/orders.json` / 忽略 | **忽略**。提交一个空 JSON 会让每次本地测试产生脏 diff；改为提供 `data/orders.example.json` 说明结构，运行时自动创建 |

## 4. 接口契约（AI 给出、后续实现遵循）

```http
POST /api/orders
{ "items":[{ "dishId":"d1", "qty":2, "unitPrice":3200, "specDesc":"份量:加大" }],
  "address":{ "name":"张三","phone":"13800000000","building":"3 号楼","room":"502" },
  "remark":"少冰" }
→ 200 { "code":0, "data":{ "id":"20261028120304-4821", "status":"pending",
                          "subtotal":6400, "deliveryFee":0, "packFee":200, "total":6600 } }
→ 400 参数错误 / 菜品不存在 / 单价低于菜品基础价
→ 409 库存不足
```

- `GET /api/orders?limit=50`：按创建时间倒序返回；
- `PUT /api/orders/:id`：`{ "status": "accepted" | "done" | "canceled" }`，非法流转直接 400。

## 5. 验证记录

见提交说明与 `README.md` 第 4 节自检清单，核心三项：

1. `POST /api/orders` 后进程重启，`GET /api/orders` 仍返回该订单；
2. 下单后 `GET /api/menu` 中对应菜品 `stock` 减少，后台刷新可见；
3. 库存置 0 后再下单返回 409，前端 Toast 提示且不跳转。

## 6. 遗留问题

- 订单文件容量：当前只做「保留最近 N 条」的截断，未做分页与归档；
- 并发：多个请求同时下单时，`readMenu` → 扣减 → `writeMenu` 之间存在竞态窗口；单机演示场景可接受，生产需加写锁；
- 无鉴权：`GET /api/orders` 任何人可读，含手机号与地址，已在 README「已知限制」中标注。
