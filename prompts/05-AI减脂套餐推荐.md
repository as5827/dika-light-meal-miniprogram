# 05 · AI 个性化减脂套餐推荐

- **日期**：2026-10-28
- **怎么做的**：我提需求和验收标准，AI 出方案、写代码
- **对应提交**：`feat(recommend): 推荐引擎与接口` → `feat(ui): H5/小程序 AI 定制页` → `docs: 创新点与文档同步`
- **上游需求**：把「内置 AI 个性化减脂套餐推荐，结合用户身体指标给出适配餐品」从一句话变成可点开的功能

---

## 1. 需求

> 本项目为减脂餐创业商家打造轻量化点餐小程序……业务层面：面向小微轻食商家，提供低成本数字化接单方案，内置 AI 个性化减脂套餐推荐，结合用户身体指标给出适配餐品，同时双前端架构兼顾真实业务落地与评审演示便捷性。

拆出来是一个明确的功能：**用户输入身体指标 → 系统给出这一餐该吃什么 → 能直接下单**。

## 2. 拆解

| 层 | 交付物 | 验收标准 |
|---|---|---|
| 数据 | 菜品补 `protein`（克） | 28 道菜全部有值，并声明为估算 |
| 算法 | `server/recommender.js` | 同输入同输出；每步可解释（BMR/TDEE/目标/偏差） |
| 接口 | `GET /api/recommend/options`、`POST /api/recommend` | 参数非法 400；全售罄 409 |
| 展示 | H5 定制页、小程序定制页 | 表单 → 结果 → 一键加购 |
| 说明 | README / 技术文档 / 本记录 | 讲得清「为什么不是随便调个大模型」 |

## 3. 取舍

| 决策点 | 备选 | 选择与理由 |
|---|---|---|
| 推荐由谁算 | 直接调大模型生成套餐 / 本地营养学模型 + 组合搜索 | **本地模型**。推荐结果要能复现、要能解释、要零成本——大模型每次输出都可能不同，评审问「为什么是这份」时答不上来。大模型只用于**文案增强**（见下） |
| 大模型角色 | 不用 / 用来算 / 用来润色 | **只润色**，默认关闭：配置 `LLM_API_KEY` 才调用，Prompt 里写死「只改语气，不得改动任何数字」，失败自动回落模板文案。实测见第 5 节 |
| 推荐粒度 | 全天三餐 / 单餐 | **单餐（全天 40%）**。用户是在点一餐，不是在做营养规划 |
| 目标函数 | 只按热量 / 热量 + 蛋白 + 价格 | 三项加权：蛋白达成 0.5、热量偏差 -0.35、价格 0.15；另加**蛋白过量惩罚**（超过目标 1.3 倍开始扣分），否则算法会无脑堆鸡胸肉 |
| 预算无解 | 返回失败 / 忽略预算 / 给最便宜的合规组合 | **最便宜且满足营养下限（蛋白 ≥60%、热量 ≥70%）**，同时在结果里标注 `budgetRelaxed`，让用户知道放宽了 |
| 营养数据 | 不写 / 精确值 / 估算值 | **估算值 + 数据文件里写明 `nutritionNote`**。伪造"实验室级"数据比承认估算更不诚实 |

## 4. 计算链路

```
身体指标 → Mifflin-St Jeor
  BMR = 10×体重 + 6.25×身高 − 5×年龄 + (男 5 / 女 −161)
→ TDEE = BMR × 活动系数(1.2 / 1.375 / 1.55 / 1.725)
→ 每日目标 = TDEE × 目标系数(减脂 0.8 / 维持 1.0 / 增肌 1.1)，并设下限 1200/1400/1600
→ 蛋白目标 = 体重 × (1.6 / 1.2 / 1.8) g
→ 单餐预算 = 目标 × 40%
→ 组合搜索：主菜(1) × 加料(0-1) × 汤/果汁(0-1) × 甜点(0-1)，约 1.5k 组合
→ 目标函数打分，取最高
```

## 5. 验证

| 用例 | 输入 | 结果 |
|---|---|---|
| 手算核对 | 女 28 岁 165cm 58kg 轻度 | BMR 1310 / TDEE 1801，与手算 1310.25 / 1801.6 一致 |
| 正常推荐 | 同上，减脂 | 鸡胸肉藜麦沙拉 + 额外鸡胸肉 + 番茄时蔬汤 = 530 kcal / 59 g / ¥57，热量偏差 −8% |
| 素食过滤 | 男 72kg，`vegetarian` | 三项全部为素食菜品（牛油果藜麦能量碗 / 南瓜浓汤 / 抹茶豆腐慕斯） |
| 预算过低 | 女 52kg，预算 ¥10 | `budgetRelaxed=true`，退化为最便宜的合规组合（全麦鸡胸三明治 ¥26） |
| 确定性 | 同参数请求两次 | 菜品 id 完全一致 |
| 非法参数 | `age: "x"` | 400 + 中文提示 |
| 大模型润色（真实调用） | DeepSeek，`useAI: true` | 返回 `aiReason`，11 个数字（1312 / 1804 / 1443 / 91 / 40% / 577 / 36 / 590 / 55 / +2% / 153%）与模板完全一致，只把语气改得更口语 |
| 坏 Key 兜底 | 传一个无效 Key | 0.3 秒返回，`aiReason` 为空，`reason` 仍是模板文案，接口 200 不受影响 |

## 6. 没做的

- 蛋白为估算值，未做碳水/脂肪/膳食纤维，也未做过敏原与忌口过滤；
- 未利用历史订单做协同过滤（现在是个体化，不是"越用越准"）；
- 大模型润色已用 DeepSeek 实测，但没有做多模型对比与成本核算，也没有对生成文案做敏感词过滤；
- 小程序端同 H5 一致地只做静态类型检查，UI 未在模拟器验证。
