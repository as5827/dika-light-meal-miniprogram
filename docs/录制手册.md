# 演示视频录制手册

> 目标：5–8 分钟的 MP4，1080p；其中**至少 2 分钟**是"AI 协同过程复现"。
> 本手册按 6 分 40 秒设计，实际落在 6–7 分钟都算合规。

---

## 一、录之前的环境（照着改，10 分钟）

| 项 | 要求 | 为什么 |
|---|---|---|
| 分辨率 | 显示设置改成 **1920×1080，缩放 100%** | 你现在的屏是 1707×1067（缩放后的逻辑分辨率），直接录出来不是标准 1080p，评委会看到"非 1080p" |
| 浏览器缩放 | 110% | 录出来字够大，1080p 下不糊 |
| 通知 | 关掉微信/QQ/系统通知（专注助手打开） | 弹窗进画面就得重录 |
| 任务栏 | 自动隐藏 | 画面干净 |
| 鼠标 | 打开"指针轨迹"或加大指针 | 评委能跟上你的操作 |
| 麦克风 | 先录 10 秒试听，确认没有电流声 | 声音糊了整段白录 |
| 演示数据 | 先跑 `node scripts/seed-demo.js 10` | 看板、订单列表空着很难看 |
| 窗口 | 左 H5 点餐页、右后台，各占一半 | 状态推送那段要并排看 |

**工具二选一**：

- **最快**：`Win + G` 打开 Xbox Game Bar → 点录制（录当前窗口），1080p、带麦克风，不用装东西；
- **更好控制**：OBS（录显示器 + 麦克风，输出 1920×1080、30fps、码率 8000Kbps）。

不推荐用手机拍屏幕——文字会糊，而且 1080p 不达标。

## 二、分段录制（一段一段录，最后拼，出错只重录一段）

### 第 1 段｜片头 0:00–0:20

- 画面：标题卡（`docs/video/title.png`，我已经生成好）
- 旁白（逐字）：
  > "这是给校园周边轻食小店做的一套点餐系统。一套后端，两个前端：小程序准备上架，网页版用来演示。核心是两块——商家能改菜单、能看经营，顾客能按自己的情况算出这一餐该吃什么。"

### 第 2 段｜功能演示 0:20–2:20（2 分钟）

一镜到底，慢一点，别剪。

1. **点餐页**（40 秒）：切两个类目 → 选"鸡胸肉藜麦沙拉" → 加购 → 指一下购物车角标的"共 990 kcal"。
   > 旁白："热量是菜品的一级字段，加购时实时累计，顾客不用自己算。"
2. **一句话点餐**（40 秒）：在顶部输入 `500 卡以内、高蛋白、不要香菜，预算 40` → 点"AI 解析" → 等结果出来 → 指一下三个条件标签。
   > 旁白："这句话被拆成三个条件，再在本地筛菜单。模型只负责理解，筛选不在模型里做。"
3. **AI 定制套餐**（30 秒）：点「AI 定制减脂套餐」→ 填女/26/165/58/久坐/减脂 → 生成 → 读数字。
   > 旁白："基础代谢 1320、日常消耗 1815，这餐预算 581 千卡；推荐三道一共 590 千卡、蛋白 55 克。"
4. **下单 + 后台接单**（30 秒）：提交订单 → 切后台 → 点"接单" → **切回跟踪页等 5 秒**，看状态自己跳。
   > 旁白："顾客端每 5 秒问一次服务端，商家一接单，这边不用刷新就变了。"

### 第 3 段｜经营看板 2:20–3:10（50 秒）★ 这一段决定"产品闭环"的分

- 画面：后台「经营看板」区块
- 操作：指指标卡 → 指热销 Top5 的绿条 → 点右上角「AI 解读」→ 等 3 条建议出现
- 旁白（逐字）：
  > "商家这边不只是订单列表。今天几单、多少钱、什么卖得好、几点最忙，一屏能看完。点 AI 解读，模型读的是同一份数字，只负责把它说成人话——数字还是服务端算的。"

### 第 4 段｜AI 协同复现 3:10–5:40（2 分 30 秒）★ 硬性要求，不能少于 2 分钟

这一段必须是**真实屏幕操作**，不能放 PPT。分三个小节：

**A. 我是怎么给它下约束的（50 秒）**

- 打开 `server/intent.js`，滚动到 `SYSTEM_PROMPT`
- 旁白：
  > "这是给模型的系统提示。我把它锁死成一个 JSON 结构：热量上限、蛋白下限、价格、忌口，不知道的一律填 null，不许猜。temperature 设 0，同一个输入不会给你两个答案。"
- 再打开 `server/stats.js` 的 `SYSTEM_PROMPT`：
  > "看板这边也一样：只准依据给出的数字写建议，不许编数字。"

**B. AI 生成的核心代码长什么样（50 秒）**

- 滚动展示 `parseWithLLM` 与 `fallbackParse`
- 旁白：
  > "模型这条链路我留了一个兜底：超时、报错、返回空条件，就走正则解析。'500千卡以内''不要香菜''预算40'这些说法，正则就能覆盖大半。所以没配 Key 也能用，只是没那么聪明。"
- 切到命令行，跑一次自测：
  ```
  node scripts/selftest.js
  ```
  > "整套接口有 73 项自测，每次改完我都会跑一遍。"

**C. 一次真实的修 Bug（50 秒）★ 这段最能体现"人引导 AI"**

- 打开 `server/intent.js`，停在 `num()` 那几行
- 旁白：
  > "第一版这里没判断空值。JavaScript 里 `Number(null)` 是 0，不是 NaN——所以模型没解析出蛋白时，条件里会多出一个'蛋白 ≥ 0'，筛选结果全被它带偏。我是在自测里看到'价格 ≤ ¥1'这种鬼条件才发现的，改成先挡掉 null 再转数字。"
- 指一下代码注释：`// 注意 Number(null) === 0，必须先挡掉`
- 再跑一次那条"预算30，来碗热的"，展示 `dropped=["想吃热"]`：
  > "筛不到的时候不是硬推，会逐级放宽，并且告诉你放宽了什么。"

### 第 5 段｜可复现性 + 收尾 5:40–6:40（60 秒）

- 切 GitHub 仓库：提交列表滚一下（43 条）→ 点开 `prompts/` → `snapshots/` 三份 → Actions 绿标
- 旁白：
  > "提交是按功能拆的，每条都能在 prompts 里找到对应的记录。CI 每次 push 都跑语法检查、类型检查和 73 项自测。"
- 快剪：新终端 `node server/server.js` → 浏览器打开 localhost:3000 → 3 秒出菜单
  > "clone 下来不用装依赖，一条命令就能跑。"
- 结束卡（`docs/video/end.png`）
  > "小程序端已经能在开发者工具里跑，还没接微信登录和支付；上架要过备案和餐饮类目资质，这些是账号侧的准备工作。代码都在仓库里。"

## 三、剪辑与导出

1. 把 5 段拖进剪映/必剪，按顺序拼，去掉开头结尾的空白和等待；
2. 段与段之间加 0.3 秒淡入淡出即可，别加花哨转场；
3. 加字幕（剪映"识别字幕"一键生成，校对一遍错别字）；
4. 导出：**MP4 / H.264 / 1920×1080 / 30fps / 8Mbps**，文件名 `dika-演示视频-1080p.mp4`。

## 四、交之前自检

| 检查 | 标准 |
|---|---|
| 时长 | 5–8 分钟（建议 6:30–7:00） |
| AI 协同段 | 单独掐表，**≥2 分钟**，且是真实操作 |
| 分辨率 | 播放器里显示 1920×1080 |
| 声音 | 全程听得清，没有突然变小 |
| 内容 | 不出现密码、API Key、别人的隐私信息 |
| 备份 | 同时传一份到 B 站（设为不公开），防止文件损坏 |
