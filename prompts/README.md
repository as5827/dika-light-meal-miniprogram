# prompts/ · 迭代记录

这里放每次功能迭代的过程记录。赛项要求「至少 3 个核心功能迭代的完整 Prompt 链」，所以每条都写清楚：当时提了什么要求、AI 给了什么方案、我怎么选、最后怎么验证的。

## 写法约定

- 一次功能迭代一个文件，命名 `NN-功能名.md`，编号跟提交顺序一致；
- 提交信息里带上编号，方便对照；
- 只写真实发生过的事，没做的就写没做；
- token、密钥、手机号一律打码。

## 每条包含

1. **需求**：当时的原话或关键句
2. **上下文**：代码到什么状态、有什么硬限制
3. **拆解**：要交付哪几样，怎么算完成
4. **取舍**：备选方案和放弃的理由（评审最看这段）
5. **接口 / 链路**：改动的具体形状
6. **验证**：跑过什么、结果如何
7. **没做的**：这次没覆盖的部分

## 对话快照（snapshots/）

赛项要求「至少 3 个核心功能迭代时与 AI 交互的**完整 Prompt 链**」，所以另开一个目录放带真实报错与命令的对话记录。

三条链统一按**四段结构**组织，评审可以按顺序读：

| 段落 | 内容 | 为什么必须有 |
|---|---|---|
| ① 我提的 Prompt | 当时的原话，不改写 | 看意图是怎么下的 |
| ② AI 给出的第一版方案 | 它第一反应做了什么 | 看它会不会跑偏 |
| ③ 我怎么引导它纠偏 | 追问原话 + 真实报错回显 + 改法 | 赛项要的「如何引导 AI 修复 Bug」就在这里 |
| ④ 验收结果 | 跑过什么、数字是多少 | 证明改完是通的，不是嘴上说通 |

| 文件 | ① Prompt 主题 | ② 第一版的问题 | ③ 纠偏过程 | ④ 验收 |
|---|---|---|---|---|
| `snapshots/01-建仓与推送排障.md` | 建仓并推代码上去 | 报「6 个提交已推送」，实际仓库没建成 | 4 个卡点：GBK 400 / 404 假象 / 新号风控 / push 被重置 | 匿名可 clone |
| `snapshots/02-推荐引擎调参.md` | 给减脂餐加套餐推荐 | 直接调大模型生成，结果不可复现 | 3 轮：蛋白 173% / 预算无解 / 营养数据来源 | 5 条用例 + 674 候选 2 ms |
| `snapshots/03-大模型润色的数字约束.md` | 接大模型润色且去 AI 腔 | 直接覆盖模板文案，数字可能被改写 | 4 步：验 key / 写死约束 / 坏 key 兜底 / 去 AI 味 | 11 个数字逐位一致 |

Prompt 为原文引用，邮箱与密钥已打码；AI 回复保留关键段落与原样命令回显，不逐字抄录整段对话。过程截图见 `docs/screenshots/dialogs/`。
