# 06 · 运行日志与 CI

- **日期**：2026-10-29
- **对应提交**：`feat(log): 结构化日志` → `ci: 冒烟工作流` → `docs`
- **上游问题**：出问题时只能靠复现，推荐为什么选这三样、订单金额怎么算出来的，全靠猜

---

## 1. 需求

> 继续完善这个程序的日志，就是包括 AI 推荐计算热量什么的

要的不是 `console.log('here')`，而是能回答三个问题：这单为什么是这个价、这套餐为什么这么推、这次请求为什么慢。

## 2. 拆解

| 交付 | 验收 |
|---|---|
| 结构化日志模块 | 一行一条 JSON，可 `jq` 直接过滤 |
| 请求日志 | 只有 `/api/*`，带状态码与耗时 |
| 推荐日志 | 指标 → BMR/TDEE → 目标 → 候选数 → 选中组合 → 偏差，一条看全 |
| 订单日志 | 金额拆分、热量、菜品；状态流转记 from/to |
| 认证日志 | 成功/失败/锁定，绝不落密码 |
| 脱敏 | 手机号、口令、token 落盘前替换 |
| CI | 语法 + 类型 + 接口冒烟，push 自动跑 |

## 3. 取舍

| 决策点 | 备选 | 选择与理由 |
|---|---|---|
| 日志格式 | 自由文本 / 结构化 JSON | **JSON Lines**。文本日志想统计"推荐平均耗时"只能写正则，JSON 直接 `jq` 聚合 |
| 依赖 | winston / pino | **零依赖**，与项目一贯的约束一致；功能只要"分级 + 落盘 + 滚动"，自己写 90 行足够 |
| 落盘策略 | 每请求一个文件 / 单文件不滚 / 单文件 + 按大小滚 | **单文件 + 5MB 滚动保留一份**。小服务器最怕日志把磁盘写满 |
| 静态资源 | 全记 / 不记 | **不记**。图片和页面会把真正有用的 API 日志淹掉 |
| 脱敏位置 | 打印时 / 写入前 | **写入前统一 sanitize**，控制台和文件都不会漏；靠"记得别打手机号"迟早出事 |
| 推荐耗时 | 只记总耗时 | **另记候选组合数**。菜单从 28 道加到 60 道时，候选数会先于耗时暴露问题 |
| CI 范围 | 只跑语法 / 加类型与冒烟 | **语法 + 类型 + 冒烟**。这个项目没有测试框架，冒烟是最低成本的行为回归 |

## 4. 日志事件

```json
{"ts":"2026-10-29T14:14:37.861Z","level":"info","event":"recommend",
 "profile":{"gender":"female","age":26,"height":165,"weight":58,"activity":"light","goal":"cut",
            "bmr":1320,"tdee":1815,"targetCalorie":1452,"proteinTarget":93},
 "mealTarget":581,"mealProteinTarget":37,"candidates":704,"elapsedMs":6,
 "picked":["d9","d26","d18"],
 "totals":{"calorie":590,"protein":55,"price":5100},
 "match":{"calorieDiffPct":2,"proteinPct":149},"budgetRelaxed":false,"vegetarian":false}
```

这条记录把"为什么是这套"完整还原了：指标 → 代谢 → 目标 → 预算 → 搜了多少组合 → 选中哪三道 → 偏差多少。

## 5. 验证

| 用例 | 结果 |
|---|---|
| 启动 | `server.start` 记录端口、管理员账号、日志路径 |
| `GET /api/menu` | `http` 事件，200，6ms |
| `POST /api/recommend` | `recommend` 事件，候选 704 组、耗时 6ms、选中 d9/d26/d18 |
| `POST /api/orders` | `order.create`，金额拆分 3200+500+200=3900，热量 320 |
| 错误口令 | `auth.login` `ok:false`，fails 计数 |
| 正确口令 + 访问订单 | `ok:true`，随后 `GET /api/orders` 200 |
| 脱敏单测 | `{phone,password}` → `{"phone":"***","password":"***"}` |

## 6. 没做的

- 没有集中式日志服务，也没有做日志查询接口（会把内部信息暴露给前端）；
- 没有对日志做结构化采样，高并发时会全量写盘；
- 推荐日志里的 `picked` 只存菜品 id，没存当时的单价快照，菜单改价后回溯会有偏差；
- CI 只在 push/PR 时跑，没有定时巡检。
