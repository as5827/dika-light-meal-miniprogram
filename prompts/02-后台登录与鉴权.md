## 2. 拆解

一句话：**把「后台」这个角色显式建模出来，而不是靠前端藏按钮。**

- 服务端：会话签发 / 校验 / 失效 + 受保护接口清单 + 登录失败限速；
- 后台页：启动先探测会话，未登录弹登录遮罩；接口返回 401 时统一回到登录态；
- 顾客端：不受影响（下单、查自己的订单仍需匿名可用）。

## 3. 取舍

| 决策点 | 备选 | 选择与理由 |
|---|---|---|
| 会话载体 | JWT / HttpOnly Cookie + 服务端 Map / Basic Auth | **Cookie + 内存 Map**。零依赖下 JWT 要自己实现 HMAC 与过期校验，收益不大；Basic Auth 每次请求带密码，浏览器体验差且无法主动登出；内存 Map 重启即失效，正好符合「演示态」定位，代价写进限制说明 |
| Cookie 属性 | 普通 Cookie / HttpOnly + SameSite | **HttpOnly + SameSite=Lax + Path=/**。HttpOnly 挡 XSS 偷 token，SameSite 挡跨站请求伪造；不过 HTTPS 环境下还应加 `Secure`，本地 http 调试加不了，已记入遗留 |
| 口令比对 | `===` / 哈希后 `timingSafeEqual` | **哈希后定时安全比较**。原始字符串比较会因长度/前缀提前返回而泄漏时序信息，`timingSafeEqual` 要求等长，所以先各自 SHA-256 |
| 会话续期 | 固定过期 / 滑动续期 | **滑动续期**（每次命中延长到 8 小时）。演示时不会写着写着被踢出去 |
| 暴力破解 | 不限 / 全局计数 / 按 IP 计数 | **按 IP 计数**，5 次失败锁 60 秒。全局计数会被一个人锁死所有人 |
| 默认口令 | 硬编码 / 环境变量 | **环境变量优先，缺省 `admin`/`dika2026`**。缺省值写进启动日志与登录框提示，保证评委 `git clone` 后零配置可复现 |
| 顾客端订单查询 | 也要登录 / 凭订单号匿名查 | **凭订单号匿名查**，且 **手机号脱敏**（`136****5678`）。订单号即凭证，评委无需账号也能看到跟踪闭环 |

## 4. 接口

```http
POST /api/login    { "username":"admin", "password":"dika2026" }
→ 200 { "code":0, "data":{ "user":"admin", "expiresIn":28800000 } }
      Set-Cookie: dika_admin=<48位hex>; HttpOnly; SameSite=Lax; Path=/; Max-Age=28800
→ 401 账号或密码不正确
→ 429 登录失败次数过多，请 N 秒后再试

POST /api/logout        → 200 { "code":0 }，同时清除 Cookie
GET  /api/session       → 200 { "code":0, "data":{ "user":"admin" } } / 401

GET  /api/orders/:id    → 200 公开视图（手机号脱敏、含 events 事件链）/ 404
```

受保护清单：`PUT /api/dishes/:id`、`POST /api/upload`、`GET /api/orders`、`PUT /api/orders/:id`。
公开清单：`GET /api/menu`、`POST /api/orders`、`GET /api/orders/:id`。

## 5. 验证

| 用例 | 结果 |
|---|---|
| 未登录 `GET /api/orders` | 401 |
| 未登录 `PUT /api/dishes/d1` | 401 |
| 未登录 `POST /api/upload` | 401 |
| 错误口令 | 401 `账号或密码不正确` |
| 正确口令 | 200，`Set-Cookie` 写入 cookie jar |
| 带 Cookie 访问 session / orders / 改菜品 | 200 / 200 / 200 |
| 登出后再访问 `/api/orders` | 401 |
| 公开下线（无 Cookie） | 200，订单正常创建 |

## 6. 没做的

- 内存会话：进程重启后全部登录态失效（评审演示需重新登录一次，属预期）；
- 未加 `Secure` 属性（本地 http 环境无法设置），部署 HTTPS 时应补；
- 登录限速只按 IP，NAT 后多人共享出口 IP 时可能互相影响；
- 没有角色区分：目前只有一个 `admin` 角色，后续若要区分店长/店员需扩展 `sessions` 里的角色字段。
