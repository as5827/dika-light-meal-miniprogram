# 对话快照 01 · 从建仓到第一次成功推送

> **第 1 条完整 Prompt 链。** 三份快照统一四段结构：
> **① 我提的 Prompt（原文）→ ② AI 给出的第一版方案 → ③ 我怎么引导它纠偏（含真实报错）→ ④ 验收结果。**
>
> Prompt 为当时原文引用；AI 回复保留关键段落与原样命令回显，不逐字抄录整段对话。

## 背景

代码已经在本地跑通（H5 + Node 后端），下一步是迁到 GitHub，让评审能公开打开。

## ① 我提的 Prompt

1. 「我参与的是个人赛 你现在先把自己接上 github」
2. 「加好了 用户名：g\*\*\*e00　我使用的账号是 g\*\*\*e@qq.com　全局一键帮我替换成 g\*\*\*e@qq.com 吧　我参加传智杯的项目名称是 dika-light-meal-miniprogram　帮我解析上传一下主体代码吧」
3. 「为什么我没有在仓库看到我的项目？」
4. 「那换 2\*\*\*\*\*\*\*\*@qq.com 这个账号你看可以不可以」

> 邮箱与账号已打码——它们能直接反查到本人，没必要留在公开仓库里。

## ② AI 给出的第一版方案

> 「仓库已建，6 个提交已推送。」

**结论下早了。** 三件事同时发生，它只报了其中一件。真实状态是：仓库建失败了、推送实际没成、而我看到的那条"成功"只是本地命令的回显。

## ③ 我怎么引导它纠偏

我没有继续问"为什么"，而是**把每一步的原始回显贴回去**，让它按报错定位。四个卡点依次解开：

**卡点 1 · 建仓接口 400**

```
POST /user/repos → 400
{"message":"Problems parsing JSON"}
```

我第一次的追问是「仓库没建成功，接口返回的是 Problems parsing JSON，你看下是不是编码问题」——这个提示让它转到正确方向：PowerShell 5.1 把中文描述按 GBK 编码传给 `curl.exe`，GitHub 收到的是非法 UTF-8。
改法：JSON 写进 UTF-8 文件，用 `--data-binary @file` 提交。一次通过，返回 201。

**卡点 2 · "Repository not found" 不是权限问题**

`git ls-remote` 报 not found，第一反应都是没权限。实际是仓库根本没建成（上一条的 400 就是根因）。**教训：报错文本会骗人，要看它前面的那一步成没成。**

**卡点 3 · 换账号时撞上风控**

```
ssh -T git@github.com      → Hi g***e00! You've successfully authenticated
GET /users/g***e00         → 404
GET /users/g***e00/repos   → 200 []
```

SSH 能认证、公开资料却 404——账号在库里存在但未公开（新号被标记）。这种号即使推上去，评委点链接也是 404。**决定换号**，改用 `as5827`（同一台机器上有它的凭据）。

**卡点 4 · push 反复被重置**

```
fatal: unable to access 'https://github.com/...': Recv failure: Connection was reset
```

排查顺序：先怀疑仓库权限（不是）→ 再查连通性（`api.github.com` 通、`github.com` 超时）→ 最后发现系统里开着代理 `127.0.0.1:7897`，而 git 完全没走它。

```
git config http.proxy http://127.0.0.1:7897
git push → 成功
```

## 我做的三个决定

| 决定 | 依据 |
|---|---|
| 不追 `g***e00`，直接用 `as5827` | 新号 404 意味着评委打不开，比赛场景下不能赌 |
| 不把 token 写进仓库或配置 | 只从系统凭据里读，用完即走；后来改成 Cookie 会话 + 环境变量 |
| 本地目录先迁到受管位置，再删旧的 | 两份代码必然改错，只留一份 |

## ④ 验收结果

- 提交历史完整上线（先 6 条，后续迭代到 58 条）；
- 推送通道固定为「代理 + 系统凭据」，`git push` 不再需要额外参数；
- **验收方式改了**：不再看命令行回显，改成匿名接口复核——`private:false`、能否匿名 clone、README 能否不登录打开。

## 复盘

这次折腾的教训不是"命令记错了"，而是**结论下得太早**：把"我这边 push 成功"当成了"评委能打开"。后面所有验收都改成站在匿名访问者的角度复核，而不是只看自己终端的回显。
