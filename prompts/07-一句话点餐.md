# 07 · 一句话点餐

- **日期**：2026-10-29
- **对应提交**：`feat(nl): 自然语言点餐` → `docs: 文档与材料同步`
- **上游问题**：赛道的 10 个推荐方向里没有餐饮，作品容易被看成"普通点餐系统"；推荐模块又被定位成"AI 只润色"，AI 含量不足以支撑 20% 的「方法创新性与意图控制」

---

## 1. 需求

> 你全部都做然后上传 GitHub —— 让这个项目从"点餐系统 + 一个小推荐"变成"能听懂人话的点餐助手"

本来的交互是：用户翻类目、看菜品、自己算热量。改成：说一句话，系统把话拆成条件，再筛。

## 2. 拆解

| 交付 | 验收 |
|---|---|
| 意图解析接口 | 一句话 → 结构化条件；模型失败时正则兜底 |
| 条件筛选 | 热量/蛋白/价格/素食/忌口/关键词，六个维度都能生效 |
| 筛不到时放宽 | 逐级去掉最软的条件，并把"放宽了什么"回传 |
| 双端入口 | H5 菜单页顶部输入条；小程序同款 |
| 可复现 | 同一句话 + 同一菜单 = 同一结果，`temperature=0` 且筛选在本地 |

## 3. 取舍

| 决策点 | 备选 | 选择与理由 |
|---|---|---|
| 谁来解析 | 让模型直接推荐菜品 / 模型只解析条件 | **只解析**。让模型点菜，它每次给你的组合都可能不同，评审问"为什么是这三道"就答不上；解析成条件后，筛选在本地跑，结果可复算 |
| 解析失败 | 直接报错 / 猜一个默认条件 / 正则兜底 | **正则兜底**。"500千卡以内""不要香菜""预算40"这些说法用正则就能覆盖大半，配置没到位或网络抖动时也不至于功能不可用 |
| 模型输出校验 | 信任模型返回 / 逐字段校验 | **逐字段校验**：数值做范围截断，数组限制长度与条数，非法值直接丢弃，不做猜测 |
| 筛不到怎么办 | 返回空 / 自动放宽 / 自动推荐别的 | **逐级放宽并回传**。关键词 → 忌口 → 蛋白 → 价格 → 热量 → 素食，每去掉一项就记一笔，前端明说"已放宽 xxx"，不假装命中 |
| 条件怎么展示 | 只给结果 / 结果 + 条件标签 | **标签化**。用户能一眼看出模型理解对不对（比如把"高蛋白"理解成没条件），这是意图对齐最便宜的验证方式 |
| 双端一致性 | 只做 H5 | **两端都做**。小程序是生产端，H5 是演示端，功能缺一个都说不通 |

## 4. 接口

```http
POST /api/nl-order
{ "text": "我想吃500千卡以内、高蛋白、不要香菜，预算40" }

→ 200
{
  "source": "llm",              // llm | llm+fallback | fallback | none
  "conditions": { "maxCalorie": 500, "maxPrice": 40, "excludeKeywords": ["香菜"], ... },
  "tags": ["热量 ≤ 500 kcal", "价格 ≤ ¥40", "不要香菜"],
  "dropped": [],                // 被放宽掉的条件
  "dishes": [ { "id": "d13", "name": "香煎鸡胸配时蔬", "calorie": 330, "protein": 33, ... } ]
}
```

## 5. 验证

| 用例 | 结果 |
|---|---|
| "500 千卡以内、高蛋白、不要香菜，预算 40" | `source=llm`，条件解析为热量 ≤500 / 价格 ≤40 / 不要香菜，命中 8 道，前三是香煎鸡胸(330kcal/33g)、鸡胸藜麦沙拉(320/32)、清蒸龙利鱼(260/28) |
| "来点素的，热量别超过 300" | 只筛选素食，命中 7 道，首位抹茶豆腐慕斯 190kcal |
| "想吃鸡胸，蛋白 25 克以上" | 命中 3 道，蛋白全部 ≥25g |
| "预算 30，来碗热的" | 关键词"热"无匹配 → 自动放宽，`dropped=["想吃热"]`，返回价格 ≤30 的 8 道 |
| 未配置 Key 时的同一句话 | `source=fallback`，正则解析出热量/价格/忌口，结果与模型版接近 |
| 小程序端 `tsc --noEmit` | 0 error |

## 6. 没做的

- 不做多轮追问（"再来点清淡的"这类依赖上下文的说法，当前每次独立解析）；
- 不做方言与错别字纠正，正则兜底只覆盖常见句式；
- 模型解析结果没有做缓存，同一句话重复请求会重复计费；
- 没接菜单之外的知识（比如"适合增肌的"这种需要营养学推理的说法，只能落到关键词）。
