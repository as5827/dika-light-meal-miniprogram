# 对话快照 03 · 让大模型只改语气，别动数字

> **第 3 条完整 Prompt 链。** 四段结构：**① 我提的 Prompt（原文）→ ② AI 给出的第一版做法 →
> ③ 我怎么引导它纠偏（四步）→ ④ 验收结果。**
>
> Prompt 为当时原文引用，`sk-` 开头的 key 已脱敏。

## ① 我提的 Prompt

> API key: sk-\*\*\*\*（已脱敏） 调用一下试试 并且再编辑润色文档和日志 尽量去除 ai 痕迹

两个要求叠在一句话里：**真的打通大模型**，**文档别写成一嘴 AI 腔**。这两件事其实是同一件事——都在问"AI 的输出能不能被人拿去用"。

## ② AI 给出的第一版做法

直接把 `plan.reason` 丢给模型："你是营养师，请润色这段话"，然后把返回的文本覆盖模板文案。

**问题在这里**：推荐结果里全是算出来的数（BMR、目标热量、蛋白克数、偏差百分比）。模型一旦"顺手改写"，前面的算法就白算了——而且这种错**肉眼很难发现**，因为它读起来更顺。

## ③ 我怎么引导它纠偏（四步）

### 第一步：先确认 key 能用，不接业务

先不碰业务代码，直接打 `POST /v1/chat/completions`：

```
HTTP 200 · model: deepseek-flash
choices[0].message.content: 减脂期保证蛋白质摄入，是因为……
```

能通，再往 `/api/recommend` 的 `useAI` 分支里接。**先把外部依赖单独验通，再合进主链路**——这跟快照 01 里"结论下太早"是同一个教训的反面用法。

### 第二步：把"不许动数字"写进系统提示

```
你是一位耐心、鼓励型的营养师。你只能改写语气，不得修改、新增、删除任何数字或结论；
输出 120 字以内中文，不要分点。
```

同一份数据，两次输出对比：

```
模板：……这套组合合计 590 kcal、蛋白 55 g，热量偏差 +2%，蛋白达成 153%。
润色：……你这套组合合计 590 kcal、蛋白 55 g，热量只偏差 +2%，蛋白达成 153%，挺不错的，继续加油！
```

### 第三步：测不确定的情况

把 key 换成一个无效值再请求：

```
code=0，aiReason 为空，reason 仍是模板文案，耗时 0.3s
```

接口不报错、页面不缺内容，只是少了那句"继续加油"。结论写进 `prompts/05` 和 README 的限制表：**大模型是增强项，不是依赖项**。

### 第四步：去 AI 味（这条比接 key 麻烦）

我的追问：「文档里这几段还是 AI 腔，设问句和自我表扬太多，重写」。改了三类：

| 原来 | 改成 | 为什么 |
|---|---|---|
| 本章回答一个问题：在「代码主要由 AI 产出」的前提下…… | 这一章的疑问很具体：代码主要由 AI 产出时，人靠什么保证结果不走样。 | 设问句 + 长定语是典型的模型腔 |
| 几个刻意的设计：**蛋白过量要扣分**…… | 几处取舍：蛋白质超过目标 1.3 倍开始扣分…… | "刻意的设计"是在自我表扬，读着假 |
| **诚实声明：** ……伪造的 Prompt 链在评审追问下必然崩塌 | **说明：** 最早的 6 次提交早于归档机制，这里也不补写。 | 解释"我为什么诚实"本身就是表演 |

另外把 `prompts/*.md` 的标题统一成「需求 / 拆解 / 取舍 / 接口 / 验证 / 没做的」，去掉「AI 的拆解」「协作形态：DSH Agent 会话」这类标签——**标签是给机器看的，记录是给人看的**。

## ④ 验收结果

逐位比对模板与润色后的文本：

```
1312 / 1804 / 1443 / 91 / 40% / 577 / 36 / 590 / 55 / +2% / 153%
```

**11 个数字全部一致。** 加上坏 key 的兜底测试，这两条一起写进了自测用例。

## 复盘

"让 AI 写得像人"最容易走偏的地方，是把它改得更花哨。实际有效的只有三件事：**去掉自我评价、去掉设问和排比、把每句话落到具体数字和具体动作上**。第三点尤其重要——"处理了并发问题"是空话，"先写菜单再写订单，最坏是少卖而不是超卖"才是人写的。

同一个道理反过来用也成立：**让 AI 别动数字，靠的不是嘱咐它，而是给它一个不许动的硬约束，再逐位比对验收。**
