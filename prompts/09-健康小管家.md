# 09 健康小管家：让推荐记住「你」

## 需求

> 「最好可以再在这个里面接入一个健康小管家，如果多次点餐具备记忆功能，主动点进去 ai 小管家对此做出建议」

三个硬要求：**多次点餐要有记忆**、**主动给建议而不是等提问**、**界面要做好看**。

## 上下文

已有两个 AI 入口（套餐推荐、一句话点餐），都是一次性计算、不保存任何用户状态。
订单里有 `address.phone`，但没有用户表；`data/` 下只有 `menu.json` 与 `orders.json`。

## 拆解

| 要交付 | 判据 |
|---|---|
| 记忆 | 换手机号即换人；同一手机号第二次进入能看到基于历史的数字 |
| 主动建议 | 打开面板不等输入就有内容，且每条建议都能追到具体数字 |
| 对话 | 至少覆盖改忌口、改目标、复盘、配餐四类意图 |
| 可视化 | 有独立的入口与面板，吉祥物要有动效，不能是 emoji 占位 |

## 取舍

| 备选 | 放弃理由 |
|---|---|
| 引入向量库做「语义记忆」 | 20 单量级下没有召回价值，却要打破零依赖 |
| 让大模型记住对话历史 | 不可复现、每次不同；评审无法验证「它为什么这么说」 |
| 让用户每天打卡身高体重 | 多一步操作就少一半留存，且与本作品「点餐顺手用」的定位冲突 |
| 记忆直接复用密码学会话 | 会话 8 小时过期，撑不起「记住你」的语义 |

最终选择：**档案极轻（目标/身高体重/忌口），其余全部从订单现算**。这样记忆永远与真实行为一致，不会出现「档案说减脂、实际天天点炸物」的割裂。

## 关键 Prompt 与产出

给 AI 的约束（节选）：

```
【目标】点餐页加一个健康小管家：记忆 + 主动建议 + 对话 + 一键加购
【现状】无用户表；订单含 address.phone；已有 recommender 与 SSE 阶段流
【约束】零第三方依赖；不改动现有接口行为；建议不得让模型参与判断
【契约】GET /api/butler/profile?phone=  POST /api/butler/chat  POST /api/butler/stream
【验收】selftest 仍全绿；换手机号记忆隔离；忌口写入后推荐生效
```

## 验证

| 用例 | 结果 |
|---|---|
| 12 单同一手机号 | 面板显示 8 单 / 每餐 686 kcal / 蛋白 49 g / 蔬菜 28% |
| 「我不吃香菜」 | 档案写入 dislikes，后续推荐回复带「已避开香菜」 |
| 「今天吃什么」 | 返回 3 道组合 + 合计数字 + 一键加购按钮 |
| 换手机号 | 记忆归零，回到「先让我认识你」 |
| 回归 | selftest 73 项仍全通过 |

## 踩到的两个坑

1. **口径错位**：第一版把「日均」当分母，而目标是「每餐」，导致 6 单被算成每餐 3030 kcal。改成按单量求均值。
2. **样式串味**：建议卡片的等级类名用了 `notice`，与全局横幅 `.notice`（`display:flex; white-space:nowrap`）撞车，卡片被压成一行并裁切。改成 `lv-notice` 等带命名空间的写法。

## 没做的

- 不接体重秤与运动手环，没有外部数据源；
- 不做账号体系，手机号即身份；
- 不复用第 5.3 节之外的营养模型，蛋白仍为估算值。
